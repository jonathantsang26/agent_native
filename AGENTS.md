# Sentinel Ember — Agent Guide

Sentinel Ember reconstructs the January 2025 Eaton and Palisades fires on 3D terrain: when the fire reached each place, how it grew, which structures were damaged, where it likely started (a model estimate), and where post-fire debris flows could follow. The agent and the map share one screen: the map publishes what it shows, and the agent reads it and changes it through actions.

`/` opens `/fires/eaton`. `/fires/palisades` is the other fire. Chat lives at `/chat`; on the map, the agent sidebar opens from the header.

## Skills

Domain: `.agents/skills/fire-analyst/SKILL.md` (answering questions about a fire) and `.agents/skills/incident-map/SKILL.md` (reading and driving the map). Framework: `.agents/skills/actions/SKILL.md`, `.agents/skills/context-awareness/SKILL.md`, `.agents/skills/adding-a-feature/SKILL.md`, `.agents/skills/storing-data/SKILL.md`, `.agents/skills/security/SKILL.md`, `.agents/skills/agent-native-toolkit/SKILL.md`, `.agents/skills/agent-native-docs/SKILL.md`. Use local docs only: `pnpm action docs-search --query "<topic>"`.

## Core rules

- Answer fire questions only from the fire actions, quote figures as they return them, and tag each claim with its `[source id]`. A response guard sends back answers with figures no action returned.
- Never speculate about what started the fire or who is responsible. Never write a street address or single out a home.
- The ignition estimate is a statistical back-trace, not an investigated origin. Exposure stats are associations, not effects. Arrival times between mapped perimeters are interpolated.
- After answering about a place or time, show it: `update-map` flies there, sets the replay time, turns on the right layers and marks the point.
- Never fabricate. Report failures; verify map changes with `view-screen`.

## Application state

- `navigation` (per tab): `{view, path, fireId?}`; the map is view `incident` at `/fires/<fireId>`.
- `incident-map` (per tab, mirrored globally): fire, replay time `t` (UTC) and `tLocal`, replay window, `playing`, `tab` (incident | drones | risk), `railTab` (Layers | Analysis | Evidence | Swarm | Briefs), `viewMode`, `visibleLayers`, `camera` {lon, lat, zoom, pitch, bearing}, `highlight`, `picked` (the spot the user last clicked; "here"), `selectedStructure`, `risk` {model, i15, segment}.
- `map-command` (per tab): one-shot command written by `update-map`; the map applies it and deletes it.

## Actions

Read-only fire data (GET, also exposed over MCP): `find-place`, `get-arrival-time`, `get-street-timeline`, `get-fire-state`, `get-weather`, `list-fire-events`, `count-structures-near`, `get-ignition-estimate`, `get-exposure-stats`, `fire-growth-chart` (a chart in chat). Each takes an optional `fire`; omitted, it uses the fire on screen. Screen: `view-screen` (state plus fire size and weather at the replay time), `update-map`, `navigate` (`view: "incident", fireId` switches fires). Briefs (SQL, `server/db/schema.ts`): `save-brief`, `list-briefs`, `delete-brief`; saved briefs appear live in the rail's Briefs panel.

## Code map

- `app/routes/fires.$fireId.tsx` mounts the map client-only (deck.gl and onnxruntime-web need `window`).
- `app/sentinel/` is the map UI: `stage/` (deck.gl layers), `rail/`, `dock/`, `drones/` (footage, in-browser fire detector), `state/` (zustand stores), `agent/bridge.tsx` (publishes `incident-map`, applies `map-command`).
- `app/sentinel/agent/SpotMenu.tsx`: clicking bare terrain offers to ask the agent about that spot. `app/sentinel/rail/briefs.tsx`: the Briefs panel.
- `shared/map.ts` and `shared/fires.ts` hold the vocabulary both sides use.
- `server/db/` (Drizzle schema, `getDb`) and `server/plugins/db.ts` (additive migrations) hold the briefs table.
- `server/lib/fire/` implements the fire tools over the bundled files; `guard.ts` is the response guard; `bundled/` is generated by `pnpm fire-data` from `public/data/`.
- `server/routes/api/sam.post.ts` outlines fire in a video frame with a hosted segmentation model (`MODEL_API_KEY`).
- `public/data/<fire>/` holds the precomputed layers the map loads.

- `evals/` holds the fire-analyst evals (`pnpm eval`, needs a model) and the adapter that runs them through the chat's prompt, tools and guard; `server/lib/fire/agent-config.ts` is the shared prompt and tool list.

After edits: `pnpm typecheck`, `pnpm test`, `pnpm agent-native:doctor`, and a browser check of `/fires/eaton`.
